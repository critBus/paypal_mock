API y esquemas · Estado de controles de Tropipay

Configurar «Próximos pagos» afecta solo a pagos nuevos. Cada pago conserva su propio escenario. Los datos y escenarios de PayPal/VirtualPOS se conservan al reiniciar el mock.

Los errores se aplican en la siguiente operación correspondiente. En VirtualPOS, un rechazo seleccionado se fuerza al usar el checkout, incluso si pulsas «Pago correcto».

Cambiar el estado aquí no envía un webhook. Usa «Reenviar notificación» para comprobar los eventos o abre el checkout.

Configuración avanzada: errores por operación

«times»: 1 fuerza un único fallo; -1 lo mantiene. PayPal: oauth/create/get/capture. VirtualPOS: create/get/checkout. Un delay permite simular timeout si supera el tiempo de espera del cliente.

Estado y diagnóstico

El reenvío respeta el escenario: si está configurado para omitir webhooks seguirá sin entregarlos. Selecciona «Flujo normal» para reanudar las entregas. Esta operación puede notificar al callback configurado.
